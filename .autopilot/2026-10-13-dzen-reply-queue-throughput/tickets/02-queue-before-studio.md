# 02 — Ограниченная обработка очереди до сканирования

**Требования:** R01 — истории 1, 2 и 5
**Blocked by:** 01
**Зона:** `dzen_commenter/orchestrator/loop.py`, `dzen_commenter/db/models.py`, `dzen_commenter/db/repository.py`, `dzen_commenter/db/migrations/`, `tests/orchestrator/`, `tests/db/`
**Волна:** 2
**Status:** ready

## Что должно заработать

Каждый цикл сначала обслуживает ожидающие generation и publication jobs, затем сканирует Studio. За один цикл бот берёт максимум пять generation jobs. Перед каждым реальным вызовом модели — включая shortening retry — repository атомарно проверяет скользящую часовую квоту и durable-резервирует один слот. Учёт сохраняется между циклами, рестартами и конкурирующими workers.

## Из брифа, дословно

> «обслуживать готовую очередь до долгого сканирования»
> «за цикл обрабатывать ограниченную пачку и соблюдать часовую квоту перед каждой AI-попыткой»

## Разделы спецификации

Пользовательские истории 1, 2 и 5; решения «Порядок цикла» и «Квота»; границы «Оркестратор бота».

## Критерии приёмки

- [ ] Fake page подтверждает: готовая generation queue обрабатывается до `fetch_comments()`.
- [ ] До 5 готовых jobs обрабатываются за цикл; ни один реальный AI-вызов (включая shortening retry) не выполняется без успешно зарезервированного слота в durable-журнале, а общий скользящий часовой лимит не превышается.
- [ ] Если слот недоступен после claim, matching claim безопасно возвращается в очередь без расхода попытки; stale token не меняет активное задание.
- [ ] Migration test переносит timestamps только legacy Reply-записей, входящих в текущий часовой лимит, не меняя исходные строки; после этого repository считает ledger и отказывает при исчерпании квоты.
- [ ] Repository test подтверждает сериализацию конкурирующих резервирований; успешные и неуспешные новые вызовы одинаково расходуют слот и не удваиваются после сохранения Reply.
- [ ] Публикация остаётся максимум одна за цикл и выполняется после генерации с существующей защитой от неопределённого результата.
- [ ] Ошибка Studio-сканирования не откатывает и не отменяет уже завершённую работу очереди.
- [ ] Лимит возраста 1 день, retry cooldown, claim tokens и terminal statuses не меняются.
- [ ] Слот AI-вызова сохраняется до сетевого вызова и переживает новый цикл/перезапуск; лимит учитывает неуспешные и shortening-вызовы.

- [ ] Короткий итог возвращён по контракту autopilot.
