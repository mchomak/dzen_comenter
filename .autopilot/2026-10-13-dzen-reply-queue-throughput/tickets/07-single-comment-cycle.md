## Что должно заработать

Бот сначала продвигает уже готовые задания, затем при необходимости проверяет верх Studio. Он проводит один комментарий через generation, сохранение и первую publication attempt в общем ограниченном цикле, а при сбое возвращается к нужному этапу без повторной генерации сохранённого ответа.

## Из брифа, дословно

> «при ошибках на какой либо стадии закидываем в конец очереди с нужным статусом и таймаутом»
> «брать комментарий и сразу доводить работу над ним от начала и до конца»
> «нет смысла в глубоком проходе в studio … нам должно хватать коротких проверок»

## Разделы спецификации

Истории 1–2, 6, 8–11; решения «Цикл», «Ошибки контекста», «Неопределённая публикация» и «Studio»; швы Оркестратор и Studio adapter.

## Критерии приёмки

- [x] Каждый цикл обслуживает сохранённые публикации перед генерацией, bounded drain предшествует due scan; generation и её первая publication attempt используют один `MAX_REPLIES_PER_CYCLE` слот (default 10). Capacity окна берётся из `Settings.MAX_ACTIVE_WORK_ITEMS`.
- [x] Если scan наступил, он выполняется коротким методом; найденные новые jobs допускаются, затем обрабатываются в том же цикле только за остаток общего бюджета. Новый short scan не запускает full scan и не открывает вторую вкладку Studio.
- [x] Расписание: короткий scan сразу после старта, далее каждые 5 минут; пустое активное окно разрешает ранний scan не чаще раза в минуту после предыдущей попытки. Любая scan attempt, в том числе успешная досрочная, сдвигает следующий срок на 5 минут; scan error не прекращает очередь.
- [x] Generation проходит context → model with durable quota/timeout → atomic save → immediate publication. Ошибка fetch/save context и generation ставит retry с cooldown в хвост; отсутствие текста при успешно полученном контексте сохраняет поведение A08.
- [x] Если Reply+publication commit упал после ответа модели, повторяется persistence того же текста до следующего model call; публикационная ошибка повторяет публикацию, а unknown submit остаётся `unconfirmed` без второго submit.
- [x] Один timeout или error не блокирует следующие ready jobs; при исчерпании durable AI quota новые generation останавливаются, но публикации продолжаются в оставшемся бюджете.
- [x] Orchestrator/page tests используют fake page/provider/repository, покрывают cycle ordering, after-scan budget, scan error, повтор по нужному этапу, timeout, quota exhaustion и подтверждение публикации; Dzen tests проверяют только bounded cards и раскрытие ответов, без live login/post.
