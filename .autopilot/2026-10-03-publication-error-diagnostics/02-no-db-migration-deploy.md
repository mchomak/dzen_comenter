# 02 — Перезапуск worker без миграции БД

**Требования:** R02, R03
**Blocked by:** none
**Зона:** `docker/`, `docker-compose.yml`, `tests/test_entrypoint.py`, `tests/test_admin_app_import.py`
**Волна:** 1
**Status:** done

## Что должно заработать

Контейнер воркера по-прежнему применяет миграции по умолчанию. При явном `RUN_DB_MIGRATIONS=false` entrypoint пропускает Alembic и запускает приложение; Compose передаёт переменную именно в `app`, чтобы кодовые изменения можно было развернуть без прямых операций деплоя над БД.

## Критерии приёмки

- [ ] При `RUN_DB_MIGRATIONS` отсутствующей или равной `true` entrypoint вызывает `alembic upgrade head` перед приложением.
- [ ] При точном значении `false` entrypoint не вызывает Alembic и всё равно запускает приложение, возвращая его exit status.
- [ ] Compose передаёт переменную в сервис `app`; admin и postgres конфигурация не меняется.
- [ ] Тесты запускают fake commands и не подключаются к PostgreSQL.
- [ ] В deploy плане/операции target — только канонический `app`, с `--no-deps` и `RUN_DB_MIGRATIONS=false`.
