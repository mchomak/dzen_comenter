## Что должно заработать

Рабочий цикл использует текущий интервал из runtime-конфига для повторных уведомлений одной и той же ошибки. Telegram-клиенты уведомлений и помощника авторизации подхватывают изменившийся proxy URL при следующем запросе.

## Из брифа, дословно

> «с какой переодичностью отправлять сообщения об крахе системы, как в telegram так и на почту одно поле ввода»
>
> «чтобы можно было его менять не перезапуская бота.»

## Разделы спецификации

Истории 1, 5–6, Решения 3–4, Границы Telegram transport и supervision.

## Критерии приёмки

- [ ] `run_supervised` получает текущий cooldown через provider и отправляет повтор одинаковой ошибки только после нового интервала; новая сигнатура ошибки немедленно уведомляется.
- [ ] `build_app` подключает provider из RuntimeConfig к supervision и обоим Telegram-транспортам.
- [ ] При изменении proxy transport создаёт новый httpx client с новым URL и закрывает предыдущий при наличии `close`; пустое значение создаёт client без proxy.
- [ ] Unit-тесты проверяют дедупликацию с изменяющимся provider и смену proxy без сети.
