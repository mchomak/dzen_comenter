# 03 — Смена аккаунта Яндекс Дзена из админки

**Требования:** R05, R06, R07
**Blocked by:** 01, 02
**Зона:** `dzen_commenter/admin/`, `dzen_commenter/auth/`, `dzen_commenter/browser/`, `main.py`, `docker-compose.yml`
**Волна:** 3
**Status:** ready

## Что должно заработать

Защищённая форма принимает логин и пароль, одноразово направляет их работающему процессу по закрытому Unix-сокету и отображает результат без секретов. Рабочий процесс полностью пересоздаёт профиль/сессию браузера и повторяет существующий вход с новыми данными.

## Из брифа, дословно

> «в админку поле для смены аккаунта яндекс дзен, чтобы можно было ввести новый логин и пароль и нажать вход»
>
> «бот удалит текущую сессию, откроет сайт заново (так его точно разлогинит из аккаунта) и запустит по новой вход в аккаунт, но уже с новыми данными.»

## Разделы спецификации

Истории 7–10, Решения 5–7, Границы login control и browser session.

## Критерии приёмки

- [ ] Страница настроек содержит отдельную защищённую форму логина/пароля Дзена, пароль не подставляется в ответ, query string, runtime JSON или логи; пустые значения отклоняются до обращения к socket client.
- [ ] Контроллер и клиент используют ограниченный Unix-socket JSON protocol и безопасно сообщают о недоступности рабочего процесса без раскрытия секрета; docker-compose разделяет непубликуемый socket между `app` и `admin`.
- [ ] `PlaywrightSessionManager.change_account` сериализует доступ к браузеру, удаляет старые cookies/storage state и собственный profile только после закрытия context, запускает чистый browser и проходит имеющийся login c переданными аргументами.
- [ ] Код проходит статическую/импортную проверку, но endpoint смены аккаунта, socket-путь смены аккаунта и внешняя авторизация Дзена не запускаются в этом прогоне по прямому требованию заказчика.
