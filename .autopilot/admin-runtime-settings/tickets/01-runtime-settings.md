# 01 — Настройки интервала уведомлений и Telegram-прокси

**Требования:** R01, R02, R03, R04
**Blocked by:** —
**Зона:** `dzen_commenter/config/`, `dzen_commenter/admin/`, `tests/config/`, `tests/admin/`
**Волна:** 1
**Status:** ready

## Что должно заработать

На существующей странице настроек администратор видит и сохраняет единое поле интервала повторных аварийных сообщений (`15m`, `2h`) и поле Telegram proxy URL. Значения становятся частью runtime-конфига без перезапуска.

## Из брифа, дословно

> «в админку вывести параметр в минутах с какой переодичностью отправлять сообщения об крахе системы, как в telegram так и на почту одно поле ввода, и так чтобы его можно было задавать в минутах и часах»
>
> «вывести в админку поле куда могу вставлять прокси, чтобы можно было его менять не перезапуская бота.»

## Разделы спецификации

Истории 1–4, Решения 1–2, Границы runtime config и admin settings.

## Критерии приёмки

- [ ] RuntimeSettings и initial JSON содержат `error_notification_cooldown_seconds=900` и `telegram_proxy_url=""`; старые JSON без этих ключей корректно читаются с дефолтами.
- [ ] Админка отображает и сохраняет поле интервала в `N[mh]`, конвертируя `15m` в 900 секунд и `2h` в 7200 секунд; пустое, нулевое, дробное, неизвестный суффикс и значение свыше 24 часов получают локальную ошибку.
- [ ] Админка отображает и сохраняет поле Telegram proxy; разрешены пустое значение и валидные `http`, `https`, `socks5`, `socks5h` URL с host; остальные варианты получают локальную ошибку без потери формы.
- [ ] Покрывающие unit/API тесты проходят и не содержат реальных сетевых обращений.
