# Спецификация: настройки мониторинга, прокси и аккаунта Дзена в админке

## Задача

Администратор должен менять частоту повторных аварийных сообщений и Telegram-прокси без перезапуска процесса, а также запускать контролируемую смену аккаунта Яндекс Дзена из защищённой админ-панели.

## Решение

На странице «Настройки» появятся: единое поле интервала повторных аварийных уведомлений, поле Telegram-прокси и отдельная форма входа в Яндекс Дзен. Несекретные значения сохраняются в существующий runtime-конфиг и подхватываются рабочим процессом. Логин и пароль Дзена передаются одноразово по внутреннему Unix-сокету, не сохраняются в JSON, логах или ответах UI.

## Решения по реализации

- `RuntimeSettings` получает `error_notification_cooldown_seconds` (дефолт 900) и `telegram_proxy_url` (дефолт пустой). Это JSON-настройки без секретов, которые уже hot-reloadятся по mtime.
- В админской валидации добавляется парсер длительности `N[mh]`: пробелы по краям игнорируются, число строго положительное, верхняя граница — 24 часа. URL прокси проверяется через `urlparse` по разрешённым схемам и наличию netloc.
- `run_supervised` получает provider cooldown в секундах и считывает его только при сравнении очередной одинаковой ошибки. Это меняет поведение без перезапуска и сохраняет текущую дедупликацию по сигнатуре ошибки.
- Email больше не является fallback Telegram для аварий: `notify_error` пытается доставить одно сообщение в оба настроенных канала, изолируя ошибку одного от другого.
- `TelegramNotifier` и `TelegramAuthAssistant` получают optional provider proxy URL. Перед запросом они сравнивают нормализованное текущее значение с активным, пересоздают клиент при изменении и закрывают заменённый client, если он это поддерживает.
- Смена аккаунта использует двунаправленный JSON-протокол, одна строка запроса/ответа, поверх Unix-сокета. Админский клиент имеет ограниченный timeout. Сервер запускается внутри процесса бота, принимает только `login` с непустыми `login` и `password`, вызывает метод сессии и возвращает `{ok: bool, error?: str}`; в сообщениях об ошибке нет пароля.
- `PlaywrightSessionManager.change_account(login, password)` берёт тот же lock, закрывает context/playwright, удаляет только каталог собственного профиля `USER_DATA_DIR` и файл `STORAGE_STATE_PATH`, стартует новый persistent context и выполняет существующий вход с аргументами команды. `keep_alive`, `login`, `reset_authentication` также используют этот lock.
- Новый docker named volume для control socket монтируется в оба сервиса в одном пути. Socket не публикуется наружу; доступ к форме уже защищён `require_login`.

## Границы и швы

| Модуль | Владеет | Выставляет | Прячет |
|---|---|---|---|
| runtime config | живые несекретные настройки | `RuntimeConfig.get/save` | JSON и mtime-кэш |
| admin settings | HTML-формы и валидация ввода | `POST /settings`, `POST /settings/dzen-account` | детали JSON и Unix-сокета |
| login control | безопасная одноразовая передача команды | `DzenLoginControlClient.login`, `DzenLoginControlServer.serve_in_thread` | framing socket и таймауты |
| browser session | жизненный цикл и вход браузера | `change_account(login, password) -> bool` | Playwright context/profile/state |
| Telegram transport | отправка в Telegram с актуальным proxy | `notify`, `notify_error` | HTTP-клиент и его пересоздание |
| supervision | подавление дубликатов аварий | `run_supervised(..., error_notification_cooldown_provider=...)` | отсчёт времени и сигнатуры |

Швы для тестов: существующие `RuntimeConfig`, `TelegramNotifier` с injected client и функции `run_supervised`; для смены аккаунта — client/server socket и `PlaywrightSessionManager.change_account`. Внешний браузер и Яндекс в этом прогоне не поднимаются.
