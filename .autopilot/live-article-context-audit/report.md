# Отчёт по live-аудиту текста статей

## Итог

Фактический аудит не запущен: безопасный SSH-доступ к production-серверу отсутствует. Проверка доступных ключей показала, что SSH-agent не содержит идентификаторов, а сервер отверг key-only подключение с ошибкой `Permission denied (publickey,password)`.

Поэтому я не стал подменять требуемый результат случайными URL, старой выборкой или статическим анализом. `.txt`-файлы с извлечённым текстом и процент лишнего контента не созданы — без реальных URL это было бы недостоверно.

## Что требуется для продолжения

Нужно настроить на сервере уже доверенную аутентификацию по SSH-ключу или сертификату для этой рабочей среды. После этого безопасный процесс будет таким:

1. Read-only выборка нескольких `post_url` вида `/a/...` из PostgreSQL.
2. Локальный вызов существующего `DzenStudioPage.fetch_article_text()` для каждой URL.
3. Сохранение каждого фактического результата в `samples/article-NN.txt`.
4. Классификация article body и page chrome и расчёт raw/article/noise символов и доли шума.

Воркер, публикация ответов, запись в БД и вызовы GigaChat в этот процесс не входят.

## Независимая приёмка

Независимая проверка подтвердила, что ни production URL, ни `.txt`-выборки, ни вычисления доли шума в репозитории не появились. Локальный тест extractor прошёл: `27 passed`; он использует fake-страницы и не может подтвердить live-результат.
