# ADR-0018 — Немедленно восстанавливать Chromium после подтверждённого падения renderer

## Контекст

После подтверждённого падения Chromium renderer текущая сессия может быть непригодна. Ожидание планового keep-alive задерживает восстановление. Цикл после восстановления должен повторяться по штатному расписанию, а действие, которое могло уже начаться, нельзя отправлять повторно.

## Решение

Для известных ошибок renderer немедленно пересоздавать сессию, выполняя один перезапуск. Текущий цикл после recovery завершается ошибкой и повторяется по штатному расписанию. Если submit начался, не повторять его. Диагностику ограничить безопасными phase/reason, timings, counts, DOM attempts и необязательным JS heap.

## Почему

Для подтверждённого падения отклонено ожидание планового keep-alive. Восстановление ограничено известными ошибками renderer; остальные неоднозначные сбои не считаются подтверждением такого падения. Повтор начатого submit также отклонён из-за неопределённого результата.

## Последствия

Менеджер сессий должен распознавать известные ошибки renderer и допускать один немедленный перезапуск. Прерванный цикл идёт по штатному расписанию, а начатая публикация защищена от автоматического повтора.
