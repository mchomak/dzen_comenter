# Контекст

Смена аккаунта одновременно затрагивает сохранённое состояние, профиль браузера и операции обработки комментариев. Частичная замена состояния или параллельный доступ к браузерной сессии могут оставить сервис в неопределённом состоянии.

# Решение

Выполнять смену аккаунта под тем же lock, который защищает остальные операции браузерной сессии. Удалять только собственные профиль и storage state, запускать новую persistent-сессию и сохранять новое состояние исключительно после успешного входа.

# Почему

Один механизм синхронизации исключает одновременную обработку комментариев и переавторизацию. Отложенное сохранение не подменяет работоспособную сессию результатом неудачной попытки входа.

# Последствия

Смена аккаунта последовательно блокирует другие действия с браузерной сессией на время операции. Все будущие точки доступа к этой сессии должны соблюдать тот же lock; изменение порядка очистки или фиксации состояния требует отдельной проверки устойчивости и восстановления.
