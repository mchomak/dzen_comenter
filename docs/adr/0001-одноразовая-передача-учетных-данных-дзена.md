# Контекст

Админ-панель и рабочий процесс бота разделены, однако смена аккаунта требует передать логин и пароль процессу, который управляет браузерной сессией. Учётные данные нельзя сохранять в runtime-конфигурации, логах или ответах интерфейса.

# Решение

Передавать команду входа однократно по двунаправленному JSON-протоколу поверх внутреннего Unix-сокета. Сокет размещать в отдельном Docker named volume, подключённом к обоим сервисам по одному внутреннему пути; наружу его не публиковать.

# Почему

Unix-сокет ограничивает канал локальной связью между сервисами и позволяет рабочему процессу получать секреты только на время выполнения команды. Строчное framing-сообщение и ограниченный timeout дают предсказуемое взаимодействие без включения пароля в URL, хранилище настроек или UI-ответ.

# Последствия

Контракт команды и расположение общего socket-volume становятся частью межсервисной архитектуры. Изменения протокола требуют согласованного обновления обеих сторон. Ответы ограничиваются безопасным статусом и сообщением без учётных данных.
