# ADR-0024: Последовательная смена worker вокруг миграции журнала

## Контекст
Миграция добавляет durable-журнал AI-вызовов и переносит в него legacy timestamps Reply, используемые текущим скользящим часовым счётчиком. При выпуске требуется сохранить PostgreSQL и рабочие данные.

## Решение
Перед миграцией остановить старый worker. Создать проверяемую резервную копию PostgreSQL, применить только миграции нового commit и запускать новый worker только после их завершения. Сохранить существующий PostgreSQL volume.

## Почему
Отвергнут запуск нового worker до завершения миграции: его квотная проверка зависит от добавленной таблицы и перенесённых timestamps. Сохранение старого worker во время миграции также не соответствует заданному порядку cutover и усложняет переход между старым учётом попыток и новым журналом.

## Последствия
Во время смены worker обработка временно приостанавливается. После миграции новый worker использует заполненный журнал; резервная копия и сохранённый volume поддерживают восстановление данных без пересоздания PostgreSQL.
