# ADR-0022: Durable ledger for AI calls and atomic hourly quota

## Контекст
Часовой лимит должен учитывать успешные, ошибочные и shortening-вызовы модели. Проверка выполняется перед каждым сетевым вызовом; при сбое процесса зарезервированный слот может быть консервативно занят. История должна переживать перезапуск, а квотные резервации — сериализоваться между конкурентными запросами. При переходе нужно учесть timestamps старых Reply, попадающие в текущий скользящий часовой счётчик.

## Решение
Добавить отдельную аддитивную таблицу журнала AI-вызовов. В одной транзакции проверять скользящий часовой лимит и резервировать слот, сериализуя конкурирующие резервации. Перенести в журнал подходящие legacy timestamps Reply. Не сохранять текст комментария, автора, URL или prompt.

## Почему
Отвергнута непостоянная проверка квоты без durable-резервации: она не сохраняет учёт после перезапуска и не обеспечивает описанную сериализацию конкурирующих попыток. Сохранение содержимого запроса не требуется для подсчёта попыток и включило бы персональные данные.

## Последствия
Схема БД получает аддитивную идемпотентную миграцию; квота может консервативно расходоваться при падении между резервацией и ответом модели. Старые Reply остаются неизменными, а журнал не содержит указанных пользовательских данных.
