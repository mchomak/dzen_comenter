Один цикл работы

Бот заходит на страницу «Комментарии» в Студии, читает обсуждения и записывает результаты в PostgreSQL. Панель бота показывает историю из этой базы и даёт менять настройки.

Как бот восстанавливает вход

Сначала проверяет открытую страницу и сохранённый профиль Chromium, затем пробует загрузить состояние из файла сессии. Если есть учётные данные для автоматического входа, пробует и их. При необходимости обращается к помощнику в Telegram. Панель может передать данные для смены аккаунта по локальному каналу связи с ботом.

Что бот читает в Студии

Внешняя лента показывает свежесть комментариев. Заголовок карточки связывает их со статьёй, а раскрытые ответы идут в порядке своей ветки. На вашем скриншоте рядом с комментариями «1 м» видны вложенные ответы «3 ч». Для отсечения по возрасту эти два порядка нужно учитывать отдельно.

Как устроен текущий обход

Бот прокручивает страницу к последнему загруженному элементу, раскрывает доступные ответы и снова смотрит, сколько карточек и кнопок раскрытия есть на странице. Для завершения нужны три подряд прохода без изменения этих двух чисел. Если этого не произошло за 40 проходов, сканер сообщает об ошибке и не возвращает даже уже извлечённые комментарии.

Что проходит отбор

  • Комментарии от аккаунта бота пропускаются по имени. Текст известного собственного ответа проверяется также по истории в базе и ссылке статьи.
  • Комментарий с распознанным возрастом больше установленного лимита сохраняется с отметкой пропуска. Возраст проверяется повторно перед генерацией.
  • Сейчас разбор времени понимает только отметки в минутах. При отсутствии распознанной даты проверка возраста пропускает комментарий дальше. Поэтому настройка «1 день» пока не гарантирует отсечение по отметкам в часах или днях.
  • Если часовой лимит исчерпан, комментарий всё равно сохраняется. Новые записи можно поставить в очередь в следующих циклах. При повторном чтении запись обновляется по идентификатору, построенному из ссылки статьи, ссылки автора и текста.

Когда бот открывает саму статью

Для подготовки ответа

Бот берёт задачу из очереди и ищет сохранённый текст. Если его нет, открывает ссылку статьи в отдельной вкладке, извлекает заголовок и содержательный текст и закрывает вкладку. Ссылки на видео пропускает при чтении текста. Если текст недоступен, может составить ответ по комментарию и ветке.

Для проверки публикации

При автоотправке бот ищет исходный комментарий и возможный дубль на публичной странице. После отправки проверяет, появился ли ответ под нужным комментарием. Эта проверка нужна и в случае, когда подходящий ответ уже виден в Студии.

Особенность текущего кода. В памяти текст привязан к ссылке статьи. В PostgreSQL поиск текста идёт по общей записи страницы комментариев Студии, которую цикл присваивает всем комментариям. Сохранённый текст одной статьи поэтому может попасть в запрос для другой. Для исправления ключ сохранения и чтения нужно привязать к ссылке самой статьи.

Куда бот обращается

Дзен через браузер

Открывает страницу комментариев, прокручивает её, раскрывает ветки и открывает статьи. Для черновика ищет исходный комментарий и заполняет поле ответа в Студии без нажатия кнопки отправки. При автоотправке нажимает кнопку и отслеживает результат запроса, который отправляет Студия. Сам бот работает с элементами страницы через Playwright.

GigaChat для текста ответа

Получает токен запросом POST на адрес из GIGACHAT_OAUTH_URL. Затем отправляет запрос POST /v1/chat/completions относительно GIGACHAT_BASE_URL. Токен используется повторно до приближения срока окончания. Оба адреса берутся из настроек запуска.

Модель получает заголовок статьи, исходный комментарий, до 400 последних символов контекста ветки и инструкции из панели. Если текст статьи удалось получить, бот добавляет его и ссылку. Часть комментариев получает инструкцию с предложением перейти по ссылке или сделать другое целевое действие. Тип ответа выбирается по ключевым словам. Точный ответ SKIP означает пропуск. Если текст слишком длинный, бот один раз просит модель сократить его.

Другие подключения

PostgreSQL принимает запросы на чтение и запись истории и очередей. Telegram используется для помощи со входом и уведомлений. При настроенном SMTP сообщения об ошибках могут также уходить по электронной почте. Если выбран провайдер OpenAI, бот использует совместимый адрес из AI_BASE_URL. Генерация в адаптере YandexGPT пока не реализована.

Что хранит база

Публикации publications
Ссылка и название записи публикации. При чтении статьи туда сохраняются извлечённый текст, время получения, результат чтения и контрольная сумма содержимого. Сейчас контекст используется через общую запись Студии, как описано выше.
Комментарии comments
Идентификатор, автор, текст, связь с родительским комментарием, время публикации при распознавании и время получения. Здесь же лежат заголовок и адрес конкретного поста, контекст ветки и состояние обработки.
Ответы replies
Готовый текст, провайдер и модель, состояние, время создания или публикации, причина ошибки и отметка об использовании текста статьи. По истории опубликованных ответов бот распознаёт уже выполненную работу.
Две очереди reply_generation_queue и reply_publication_queue
Какая задача ждёт, сколько раз её пробовали, когда можно повторить, какая была ошибка и кому выдана задача. Ошибка генерации повторяет обращение к модели. Ошибка публикации повторяет работу с уже сохранённым текстом.
Как защищена отправка

Права на завершение задачи привязаны к временному ключу. Перед нажатием «Отправить» бот записывает отдельную отметку. Если после нажатия результат не удалось подтвердить, ответ получает статус «Публикация не подтверждена». Истёкшая задача с отметкой об отправке не нажимает кнопку повторно автоматически.

Какие настройки на что влияют

Из панели, применяются во время работы

Автопубликация auto_publish
При выключенной настройке ответ сохраняется в базе, а бот пытается заполнить поле в Студии. При включённой ищет нужную ветку, отправляет и проверяет появление ответа.
Возраст max_comment_age_days
Ограничивает генерацию по распознанной дате публикации. В очереди публикации код сейчас отсекает по времени получения комментария, поэтому это другая проверка. Глубину прокрутки настройка пока не меняет.
Часовой лимит max_comments_per_hour
Счётчик по записям ответов за последний час, включая черновики, ошибки и пропуски с записью ответа. Дополнительный запрос на сокращение не составляет отдельную запись.
Текст ответа
Максимальная длина, правила и запретные темы, тон, условия предложения ссылки и его частота cta_every_n_comments. Длина проверяется вместе с обращением к автору.
Повторы и уведомления
Для генерации и публикации отдельные паузы и пределы попыток. Здесь же задаются имя аккаунта бота, адресаты уведомлений, пауза между одинаковыми ошибками и прокси для отправки уведомлений Telegram.

Из окружения, читаются при запуске

Страница и сессия
COMMENTS_URL указывает, какую ленту читать. USER_DATA_DIR, STORAGE_STATE_PATH и HEADLESS задают профиль, файл сессии и видимость браузера.
Расписание
POLL_INTERVAL задаёт паузу опроса. KEEPALIVE_INTERVAL задаёт интервал поддержания браузерной сессии. Текущий цикл берёт максимум одну задачу каждого вида, это ограничение задано кодом.
Модель
AI_PROVIDER выбирает провайдера, AI_MODEL и GIGACHAT_MODEL задают модель для соответствующего адаптера. AI_TEMPERATURE, AI_MAX_TOKENS и AI_PROMPT_LANGUAGE управляют генерацией и языком инструкций.
Подключения
DATABASE_URL задаёт подключение к PostgreSQL. RUNTIME_CONFIG_PATH указывает файл живых настроек. Помощник для входа в Telegram берёт прокси из TELEGRAM_PROXY_URL при запуске. SMTP настраивается отдельно.

В локальном файле настроек указаны черновики, возраст 1 день и длина ответа до 200 символов. Настройки работающего сервера могут отличаться после изменений в панели.

Что показал сбой после переноса

Обновлённая сессия прошла проверку входа. Затем один обход достиг 40 проходов без стабилизации. Сканер успел извлечь 3 064 комментария, но завершился исключением до их записи. Код отбора по возрасту в том цикле так и не получил эти данные.

  1. Сначала научить бота надёжно читать отметки времени, включая часы и дни, и явно обрабатывать неизвестную дату.
  2. Затем ограничить обход по свежести внешней ленты. При раскрытии карточки проверять возраст каждого ответа отдельно. Остановку по возрасту строить на подтверждённом порядке внешней ленты и проверенных датах.
  3. Закрепить на примерах, что неполный обход сохраняет только надёжно прочитанные записи, повтор не создаёт дублей, а сбой чтения не мешает уже поставленным задачам. Отдельно проверить кэш на двух разных статьях.
  4. Проверять выпуск в режиме черновиков по завершённым циклам чтения и записям в базе. Статус «в процессе» показывает активность бота, а успешный обход подтверждают отдельные события в журнале.

Резервный вход через Telegram тоже требует внимания. В ходе диагностики с сервера не удалось подключиться ни к настроенному прокси, ни напрямую к Telegram. Это отдельная проблема, которая снова проявится при истечении сессии.

Карта составлена по коду в репозитории. Основные места для сверки цикл бота, работа со Студией, запись в базу, живые настройки.
